# Build issues

Running list of every place the build had to choose because the tech design (`docs/tech-design.html`) was silent, ambiguous or wrong. One row per issue: the task that hit it, the section, what was unclear, and the choice made. "Needs" says what should happen to close it: a tech-design change, a code change, or just confirmation.

## U0 Foundation

| # | Section | What was unclear or wrong | Choice made | Needs |
|---|---|---|---|---|
| 1 | §9.6, §9.1 | The design refuses `STANDINS=true` and `AUTH_IMPL=header` in production but says nothing about the stand-in queue. The build rules require all three stand-ins to be refused. | Config also refuses `QUEUE_IMPL=db` when `NODE_ENV=production`. Until a real queue adapter exists, no production configuration can start. | Tech-design change |
| 2 | §5.3 | No collation is given for `dedupe_key` / `occurrence_key`, so they inherited the table's case- and accent-insensitive collation. The unique key then merged keys that differ only in case or accent, and disagreed with the helper's exact comparison (the helper threw). | Both columns use an exact binary collation (`utf8mb4_0900_bin`, which also compares trailing spaces exactly) in `notification_deliveries` and `archived_notification_deliveries`. Nothing else in the schema differs from §5. | Tech-design change |
| 3 | §5 intro vs §7.4 / §8.3 | §5 says `created_at` is a database default and informational, but the cancellation rule compares a delivery's `created_at` with `cancelled_before`, which the application writes from its clock. | `insertDeliveries(db, rows, { now, newId? })` takes a required `now` and writes `created_at` from the application clock. Callers must pass a fresh `clock.now()` on every call: a `now` captured at job start could mark rows inserted after a reactivation as cancelled. | Tech-design change |
| 4 | §5 intro | Timestamps are "truncated to whole seconds", but MySQL rounds fractional seconds to the nearest second by default. | Connections set `TIME_TRUNCATE_FRACTIONAL`, so every write truncates. | Tech-design change |
| 5 | §5.3 | mysql2 enables `FOUND_ROWS` by default, which makes `ON DUPLICATE KEY UPDATE id = id` report a repeat as an affected row; "fewer rows inserted than sent" then never triggers. | The connection disables the flag. Consequence for every unit: `update()` returns rows changed, not rows matched, so 0 must not be read as "not found". | Tech-design change |
| 6 | §5.3 | "The statement fails and the helper returns the offending account ids" does not say whether the rest of the batch is inserted, or whether the ids are distinct. | The helper drops the unknown accounts' rows, inserts the rest, and returns distinct ids. Rows dropped for unknown accounts are not counted as `alreadyDelivered`. | Confirmation |
| 7 | Ground rules vs §5.3 | "Only `eligibility/accountsSchema.ts` may name the accounts table's columns", but the insert helper must look up which account ids are missing. | The helper queries `accounts` by `id` only (the column the foreign key already names). | Confirmation |
| 8 | §3.1 | The path rule names only `..` segments and "control characters". Percent-encoded dot segments and a literal `.` segment resolve the same way under URL parsing; Unicode format characters (zero-width, direction overrides) are not control characters. | Stricter rule: `.` and `..` segments, literal or percent-encoded, and Unicode format characters are rejected. | Tech-design change |
| 9 | §3.1 | "A full date-time with an offset" does not say which offset forms. Behaviour for a plain date when the business timezone has no midnight that day (DST gap) is undefined. | Accepted: `Z` and `±HH:MM`. A plain date on a day without a local midnight means the first instant of that local date. | Confirmation |
| 10 | §9.6 | `ASSET_BASE_URL` and `SITE_BASE_URL` have no default. Numeric settings have no stated bounds. | Both URLs are required. Numeric settings must be plain positive integers; an empty string counts as unset. | Confirmation |
| 11 | §5.8, §5.9 | The stand-in accounts migration "runs only when `STANDINS=true`", but the delivery foreign key needs `accounts` to exist first, knex records a skipped migration as applied, and the design gives no way to pass config to a migration. | The stand-in migration is ordered before the initial migration and reads `process.env.STANDINS` directly. With `STANDINS=true` it creates the table (refusing if it exists, and refusing under `NODE_ENV=production`). Without it, it requires `accounts` to exist already and fails with a clear message otherwise. | Tech-design change |
| 12 | §6.3, §8.2 | `event_delivery` carries the event type, whose union lives in `trigger/`, which `queue/` may not import. `occurredAt` is a `Date` in `TriggerEvent` but the payload is JSON. | `EventTrigger` is defined and exported in `queue/queue.ts` (trigger re-exports it). `occurredAt` is an ISO-8601 UTC string in the payload. | Tech-design change |
| 13 | §6.3 | `FakeQueue`: default `maxAttempts`, handling of `runAt`, and a job type with no handler are unspecified. | `runAt` is recorded but not honoured (jobs run when `runAll` is called). A missing handler throws immediately instead of being retried and dead-lettered. | Confirmation |
| 14 | Ground rules vs §6.3 | "All time comes from `deps.clock`", but the `Metrics` interface takes no clock and EMF lines need a timestamp. | The EMF metrics factory takes a `Clock`. | Confirmation |
| 15 | §12 | Ownership overlaps: `Deps` and `FakeQueue` (U0) need `Queue` and `AuthProvider`, whose files belong to U2 and U1; the test app factory (U0's `test/helpers`) needs U1's `createApp`; the §7.4 cancellation predicate is needed by `jobs/` and `scheduler/`, which may not import each other. | U0 creates `src/queue/queue.ts` and `src/middleware/auth.ts` as type-only files that U2 and U1 take over. U1 adds the app factory helper. The cancellation predicate lives in `src/lib/cancellation.ts`. | Tech-design change |
| 16 | §10.4 | Nothing says how several checkouts test against one MySQL server, or what stops two runs sharing a database. | `DB_NAME` overrides the database in `DATABASE_URL`; `RESOURCE_NAMESPACE` (default: the database name) namespaces server-wide names such as the scheduler lock; `npm run db -- create\|migrate\|drop <name>`; a test run holds a per-database MySQL lock, so a second run on the same database fails at once. | Tech-design change |
| 17 | §10.4 | "The seed is left in place" does not say whether a test that changes an account must restore it. | The reset helper restores accounts 1–72 to seed values and deletes any others before each test file. | Confirmation |
| 18 | §4 | `npm run lint` is required but no linter is named; no formatter is named. | ESLint with typescript-eslint as dev dependencies. Formatting is a one-off Prettier run by the orchestrator after each unit (single quotes, width 110); Prettier is not a dependency. | Confirmation |
