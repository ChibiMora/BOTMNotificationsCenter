# Build issues

Running list of every place the build had to choose because the tech design (`docs/tech-design.html`) was silent, ambiguous or wrong. One row per issue: the task that hit it, the section, what was unclear, and the choice made. "Needs" says what should happen to close it: a tech-design change, a code change, or just confirmation.

## U0 Foundation

| # | Section | What was unclear or wrong | Choice made | Needs |
|---|---|---|---|---|
| 1 | §9.6, §9.1 | The design refuses `STANDINS=true` and `AUTH_IMPL=header` in production but says nothing about the stand-in queue. The build rules require all three stand-ins to be refused. | Config also refuses `QUEUE_IMPL=db` when `NODE_ENV=production`. Until a real queue adapter exists, no production configuration can start. | Tech-design change |
| 2 | §5.3 | No collation is given for `dedupe_key` / `occurrence_key`, so they inherited the table's case- and accent-insensitive collation. The unique key then merged keys that differ only in case or accent, and disagreed with the helper's exact comparison (the helper threw). | Both columns use an exact binary collation (`utf8mb4_0900_bin`, which also compares trailing spaces exactly) in `notification_deliveries` and `archived_notification_deliveries`. Nothing else in the schema differs from §5. | Tech-design change |
| 3 | §5 intro vs §7.4 / §8.3 | §5 says `created_at` is a database default and informational, but the cancellation rule compares a delivery's `created_at` with `cancelled_before`, which the application writes from its clock. | `insertDeliveries(db, rows, { now, newId? })` takes a required `now` and writes `created_at` from the application clock. Callers must pass a fresh `clock.now()` on every call: a `now` captured at job start could mark rows inserted after a reactivation as cancelled. | Tech-design change |
| 4 | §5 intro | Timestamps are "truncated to whole seconds", but MySQL rounds fractional seconds to the nearest second by default. | Connections set `TIME_TRUNCATE_FRACTIONAL`, so every write truncates. | Tech-design change |
| 5 | §5.3 | mysql2 enables `FOUND_ROWS` by default, which makes `ON DUPLICATE KEY UPDATE id = id` report a repeat as an affected row; "fewer rows inserted than sent" then never triggers. | The connection disables the flag. Consequence for every unit: `update()` returns rows changed, not rows matched, so 0 must not be read as "not found". | Tech-design change |
| 6 | §5.3 | "The statement fails and the helper returns the offending account ids" does not say whether the rest of the batch is inserted, or whether the ids are distinct. | The helper drops the unknown accounts' rows, inserts the rest, and returns distinct ids. Rows dropped for unknown accounts are not counted as `alreadyDelivered`. | Confirmation |
| 7 | Ground rules vs §5.3 | "Only `eligibility/accountsSchema.ts` may name the accounts table's columns", but the insert helper must look up which account ids are missing. | The helper queries `accounts` by `id` only (the column the foreign key already names). | Confirmation |
| 8 | §3.1 | The path rule names only `..` segments and "control characters". Percent-encoded dot segments and a literal `.` segment resolve the same way under URL parsing; Unicode format characters (zero-width, direction overrides) are not control characters. | Stricter rule: `.` and `..` segments, literal or percent-encoded, and Unicode format characters are rejected. | Tech-design change |
| 9 | §3.1 | "A full date-time with an offset" does not say which offset forms. Behaviour for a plain date when the business timezone has no midnight that day (DST gap) is undefined. | Accepted: `Z` and `±HH:MM`. A plain date on a day without a local midnight means the first instant of that local date. | Confirmation |
| 10 | §9.6 | `ASSET_BASE_URL` and `SITE_BASE_URL` have no default. Numeric settings have no stated bounds. | Both URLs are required. Numeric settings must be plain positive integers; an empty string counts as unset. | Confirmation |
| 11 | §5.8, §5.9 | The stand-in accounts migration "runs only when `STANDINS=true`", but the delivery foreign key needs `accounts` to exist first, knex records a skipped migration as applied, and the design gives no way to pass config to a migration. | The stand-in migration is ordered before the initial migration and reads `process.env.STANDINS` directly. With `STANDINS=true` it creates the table (refusing if it exists, and refusing under `NODE_ENV=production`). Without it, it requires `accounts` to exist already and fails with a clear message otherwise. | Tech-design change |
| 12 | §6.3, §8.2 | `event_delivery` carries the event type, whose union lives in `trigger/`, which `queue/` may not import. `occurredAt` is a `Date` in `TriggerEvent` but the payload is JSON. | `EventTrigger` is defined and exported in `queue/queue.ts` (trigger re-exports it). `occurredAt` is an ISO-8601 UTC string in the payload. | Tech-design change |
| 13 | §6.3 | `FakeQueue`: default `maxAttempts`, handling of `runAt`, and a job type with no handler are unspecified. | `runAt` is recorded but not honoured (jobs run when `runAll` is called). A missing handler throws immediately instead of being retried and dead-lettered. | Confirmation |
| 14 | Ground rules vs §6.3 | "All time comes from `deps.clock`", but the `Metrics` interface takes no clock and EMF lines need a timestamp. | The EMF metrics factory takes a `Clock`. | Confirmation |
| 15 | §12 | Ownership overlaps: `Deps` and `FakeQueue` (U0) need `Queue` and `AuthProvider`, whose files belong to U2 and U1; the test app factory (U0's `test/helpers`) needs U1's `createApp`; the §7.4 cancellation predicate is needed by `jobs/` and `scheduler/`, which may not import each other. | U0 creates `src/queue/queue.ts` and `src/middleware/auth.ts` as type-only files that U2 and U1 take over. U1 adds the app factory helper. The cancellation predicate lives in `src/lib/cancellation.ts`. | Tech-design change |
| 16 | §10.4 | Nothing says how several checkouts test against one MySQL server, or what stops two runs sharing a database. | `DB_NAME` overrides the database in `DATABASE_URL`; `RESOURCE_NAMESPACE` (default: the database name) namespaces server-wide names such as the scheduler lock; `npm run db -- create\|migrate\|drop <name>`; a test run holds a per-database MySQL lock, so a second run on the same database fails at once. | Tech-design change |
| 17 | §10.4 | "The seed is left in place" does not say whether a test that changes an account must restore it. | The reset helper restores accounts 1–72 to seed values and deletes any others before each test file. | Confirmation |
| 18 | §4 | `npm run lint` is required but no linter is named; no formatter is named. | ESLint with typescript-eslint as dev dependencies. Formatting is a one-off Prettier run by the orchestrator after each unit (single quotes, width 110); Prettier is not a dependency. | Confirmation |

## U1 HTTP shell

| # | Section | What was unclear or wrong | Choice made | Needs |
|---|---|---|---|---|
| 19 | §6.2, §12 | `api.ts` must pick the queue from `QUEUE_IMPL`, but U1 depends only on U0 and the queue is built by U2 in parallel. | `api.ts` has a `selectQueue(config)` that throws "queue implementation not wired" until U2's `createQueue` is wired in after both merge. | Tech-design change |
| 20 | §9.1 | "`/admin/*` → requireAdmin" does not say where the gate is attached. The router library skips router-level middleware when no route matches (a non-admin would get 404, not 403), matches paths case-insensitively by default, and prefixes by plain string concatenation. | The gate is applied in `createApp` to every path whose lower-cased form starts with `/admin`; both routers are case-sensitive. Later units must not add the admin check again, and admin routes must live under `/admin`. | Tech-design change |
| 21 | §6.2 | `createApp(deps)` gives tests no way to exercise the gate or the error mapper against a real route. | `createApp(deps, routers?)`: an optional second argument with the routers to mount, defaulting to the real ones. The one-argument form is unchanged. | Confirmation |
| 22 | §9.1 | The middleware order does not place JSON body parsing. | Parsing runs after rate limiting and the admin gate, so a rejected request is never parsed. A non-admin sending malformed JSON to `/admin` gets 403, not 400. | Confirmation |
| 23 | §3.2 | No code exists for 405 (wrong method) or 413 (body too large). | Wrong method on an existing path → 404 `NOT_FOUND`. Body over 1 MB → 400 `VALIDATION_ERROR`. | Tech-design change |
| 24 | §9.3 | The mapping table does not cover errors raised with Koa's own `ctx.throw` / `ctx.assert`, does not define which errors count as "connection errors", and gives no way to recognise "malformed multipart". | Exposed 4xx errors map by status to the contract's codes (other 4xx → 400). A fixed list of connection error codes and knex pool timeouts → 503 with a neutral message. Malformed multipart is recognised by the parser's error messages; U5 must confirm against real uploads. | Confirmation |
| 25 | §9.5 vs §9.3 | "Notification content is never logged" conflicts with "logged with stack": the database library puts the SQL with bound values into a failed query's error message, and the driver attaches the full query to the error object. | The connection sets `compileSqlOnError: false` and strips the driver's `sql` property from query errors. Residual: MySQL's own message can quote an offending value for some errors (for example a duplicate key). Mapped 503s and lock conflicts are logged at warn. | Tech-design change |
| 26 | §9.1 | "Absent or non-numeric → 401" does not say whether `0`, negatives, decimals or leading zeros are numeric. | Only a canonical positive integer gives a session. | Confirmation |
| 27 | §9.8 | Whether the fixed window is clock-aligned, what `Retry-After` holds, and which limit applies to unknown paths are unspecified. | Window aligned to the clock minute; `Retry-After` is the seconds left in the window; unknown non-admin paths count against the member limit; health endpoints are not limited. | Confirmation |
| 28 | §11.4 | The health response body and accepted methods are not specified. | `GET` and `HEAD` on `/healthz` and `/readyz`; success body `{ "status": "ok" }`; `/readyz` failure is the 503 `UNAVAILABLE` envelope. | Confirmation |
| 29 | §10.4 | The test runner ignores "run files serially" when set per project, so database test files ran concurrently on one database. | The `test:integration` and `test:contract` scripts pass `--no-file-parallelism`. | Confirmation |

## U2 Queue (interface + stand-in)

| # | Section | What was unclear or wrong | Choice made | Needs |
|---|---|---|---|---|
| 30 | §8.1 | The claim SQL uses the database's `UTC_TIMESTAMP()`, while the ground rules say all time comes from the injected clock; tests could not drive backoff or leases without sleeping. | Every "now" in the queue is a bound value from `deps.clock`. The queue exposes manual stepping (`claim`, `poll`, `runOnce`, `upkeep`, `drain`) for tests. | Tech-design change |
| 31 | §8.1 | Completion writes match on job id alone. After a lease expires and another worker re-claims the job, the old worker's late result overwrote the new owner's row; a job could run twice at once and be dead-lettered twice. | Completion writes and `heartbeat()` are fenced on status, owner and attempt. A stale owner does nothing; `heartbeat()` throws "lease lost". A job with no attempts left is never claimed; upkeep dead-letters exhausted rows with `onDead` once. | Tech-design change |
| 32 | §8.3 | "At most `FANOUT_MAX_CONCURRENT` fan-out jobs at a time" is not specified for the claim. Applied after the `LIMIT 10` select, a burst of fan-outs stalled every other job type. | The worker runs up to 10 jobs concurrently without waiting for a batch. The claim selects fan-outs and other jobs separately, so fan-outs never block other types. | Tech-design change |
| 33 | §5.7, §8.1 | `jobs` has no completion timestamp, but `done` and `dead` rows are purged by age. | `locked_at` is set to the completion time for `done`/`dead` rows and retention is measured from it. | Tech-design change |
| 34 | §8.3 | Housekeeping must purge dead jobs, but only `dbQueue.ts` may touch `jobs` and the `Queue` interface has no purge operation. | `purgeDead` is a method on the stand-in only; housekeeping calls it when the configured queue provides it. | Tech-design change |
| 35 | §8.3, §4 | Schedules are cron expressions but no cron library is named. | `schedule.ts` implements standard five-field cron in UTC. An invalid expression fails worker start before anything runs. | Confirmation |
| 36 | §8.3 | The leader lock name is a literal, which collides across databases on one server. No probe timeout is given, and a worker that silently lost the lock could keep running leader-only timers. | The lock name derives from `RESOURCE_NAMESPACE`. Probes time out after 5 s. Ownership is verified immediately before each leader-only run. Leader-only timers must be idempotent: a brief two-leader window cannot be fully excluded. | Tech-design change |
| 37 | §8.4 | "Worker loops back off and resume" gives no growth or cap. Worker shutdown has no stated deadline. | The poll loop's wait doubles from the poll interval to a 60 s cap and resets on success. Shutdown has a 30 s deadline. | Confirmation |
| 38 | §9.5 | The per-job log line must include "rows written", which the queue runner cannot know. | The queue logs job id, type, attempt, outcome and duration. Each handler logs and counts its own rows written. | Tech-design change |
| 39 | §8.3 | An import's "current run" has no pointer in the schema; "failed for more than 30 days" has no reference column. | Current run = highest run id. Failure age is measured from `imports.updated_at`. The import handler must touch `imports.updated_at` after every chunk. | Confirmation |
| 40 | §12 | The registries are owned by U2 but list files of U5, U7, U8 and U9. "Worker starts with empty registries" contradicts a complete handler map. | U2 created those files as stubs (handlers throw "not implemented"; timers do nothing). U2's tests inject their own handlers and timers, so replacing a stub breaks nothing. | Tech-design change |
